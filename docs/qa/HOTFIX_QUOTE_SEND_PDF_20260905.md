- Production, configuration, data, mail delivery, push and deployment are out of scope.
- Test cluster: disposable PostgreSQL 18.4, loopback port 55439, database `quote_hotfix_test`. All 108 existing migrations applied. Runtime grants taken from the current production role contract; runtime is not a table owner or superuser.
- Cause: `FOR SHARE` on insert/delete-only quote items and immutable quote versions requires UPDATE. Initial snapshot also used independent READ COMMITTED queries. Draft PDF GET wrote storage/DB and UI bypassed the shared authenticated client.
- Initial restricted-role regression BEFORE application edits: 1 passed, 1 failed. `sendQuote` failed at `SELECT ... FROM quote_items ... FOR SHARE`, PostgreSQL `42501 permission denied for table quote_items`. Negative checks also reproduced the `FOR KEY SHARE` failure without UPDATE privileges.

## Implementováno

- Obě čtení snapshotu používají REPEATABLE READ. První je read-only; druhé zamyká rodičovskou nabídku, dodavatele a zákazníka a ověřuje hash před uložením verze. Položky nepotřebují UPDATE grant. Jediné aplikační INSERT/DELETE položek jsou `upsertItems`; create je transakční, update nyní ověřuje draft pod rodičovským FOR UPDATE zámkem. Změna pořadí také používá tuto výměnu položek. Žádné immutable triggery ani granty se nemění.
- Neměnné verze se čtou bez row locku. Veřejné rozhodnutí zůstává serializované přes existující zámky tokenu/rodiče a kontroluje PDF vazbu skutečně vydané verze. Admin rozhodnutí používá verzi podle vydaného PDF, nikoliv poslední neúspěšný pokus.
- Existující `api_idempotency_records`, scope `quote-delivery:v1`, eviduje pokus a jeho verzi. Session advisory lock serializuje odesílání napříč procesy. Stejný klíč přehrává výsledek; pending/ambiguous jej nikdy znovu neodesílá. UI drží klíč po dobu jednoho dialogu, blokuje dvojklik a vypíná automatický retry. Nové otevření odeslání znamená vědomý nový pokus.
- Koordinační session zámky mají samostatný pool nejvýše 4 spojení na API proces ke stejné runtime DB; nevyčerpají spojení potřebná pro doménové transakce. Test 10 různých nabídek stejného vystavitele odkryl také `40P01`: FK verze získával KEY SHARE před existujícím zámkem vlastníka tokenu. Vystavitel se nyní zamyká před INSERT verze, takže tento souběh projde bez opakování SMTP. Nevzniká nová služba, konfigurace ani migrace; provozní rozpočet DB spojení musí počítat s těmito až 4 dalšími spojeními na proces.
- SMTP běží mimo DB transakci. Explicitní odmítnutí a chyby před SMTP nejsou úspěch; nejistý SMTP výsledek nebo následný DB výpadek vrací `quote_delivery_unknown`. Záznam uchovává vazbu na verzi i při nejasném výsledku. Nejde o záruku doručení příjemci.
- Nový token před SMTP neruší starý úspěšný odkaz. Po úspěchu se atomicky aktualizuje vydaný PDF ukazatel, staré tokeny a superseded event. Dokončení vyžaduje stejný updatedAt, povolený stav a konkrétní nejnovější připravenou verzi; nepřepíše rozhodnutí ani pozdější úpravu. Cleanup cílí konkrétní token/objekt. Při nejasném COMMITu se před smazáním ověřuje zachovaná vazba; při nemožnosti ověřit zůstává PDF zachované a loguje se korelace bez zákaznického obsahu/tokenu.
- Stejný snapshot a renderer vytvářejí emailovou přílohu i uložený originál. Vlastní předmět/text zůstává, aplikační odkaz se připojuje i k vlastnímu textu.
- `Stáhnout PDF` je v detailu vedle odeslání i bez předchozího PDF/příjemce. Otevřený editor vyžaduje nejdříve explicitní uložení. Koncept používá aktuální uložený snapshot a buffer bez verzí, tokenů, změn stavu/updatedAt, storage nebo SMTP; `ensureSettings` byl odstraněn z PDF cesty.
- Vydaná nabídka stahuje původní objekt podle skutečně vydané PDF vazby; `Archiv PDF` vybírá konkrétní vytvořenou verzi přes `?version=N`, i po znovuotevření konceptu a bez veřejného tokenu. Archiv může obsahovat i zachované neúspěšné pokusy; není automaticky považován za poslední úspěšné odeslání. Starší záznam bez verze použije dostupný uložený originál. Chybějící archiv se nikdy neregeneruje.
- Doplněn parametr existujícího OpenAPI endpointu a regenerovány klient/Zod. UI používá existující generované stažení a společný klient, kontroluje MIME a `%PDF-`, uvolňuje blob URL a hlásí chyby. API vrací bezpečný attachment filename, PDF MIME, private/no-store a nosniff; JSON chyby nemají attachment hlavičku.
- Stávající A4/Roboto šablona doplněna o název, zalamování stran, dlouhých stranických údajů a poznámek, číslování stran. Snapshot zůstává schemaVersion 2, renderer je `quote-pdf-v3`; nákupní ceny/marže se do PDF nedostávají.

## Blokace a provozní předání

- **IMPLEMENTOVÁNO:** ano. **OVĚŘENO LOKÁLNĚ:** cílený workflow ano, celý povinný gate není zelený. **NASAZENO:** ne. **OVĚŘENO V PRODUKCI:** ne.
- `production-migration-host-operator.contract.test.ts` se ve zdejší povinné API sadě nenačte: `SyntaxError: Invalid or unexpected token`. Samostatný opakovaný příkaz se stejným souborem chybu potvrdil. Tento test, jeho host operator ani migrační zdroje nejsou v diffu. Přesná příčina nebyla v tomto hotfixu diagnostikována; není tvrzeno, že projde CI/Linux.
- Úklid: runner odstranil všechny dočasné databáze svých sad. `pg_ctl stop` byl systémem odmítnut; po CHECKPOINTu byl ukončen přesně ověřený testovací proces PID 9696 a ověřeno ukončení jeho potomků. Následně byl odstraněn pouze task-local `.local-test-pg` s kontrolou absolutní cesty. Ostatní PostgreSQL instance zůstaly nedotčené; syntetické PDF, screenshoty a logy zůstávají v ignorovaném `.local`.
- Nebyl proveden plný produkční login E2E, test na fyzickém telefonu, PostgreSQL 16 ani skutečný S3/SMTP provider. Místní DB je PostgreSQL 18.4 a storage je protokolový testovací sink. Nebyla provedena produkční diagnostika, obnova zálohy ani reálné doručení e-mailu.
- **Migrace: žádná.** Existující schéma 0108 a granty stačí. Záznamy nového idempotency scope jsou kompatibilní se starší aplikací; immutable snapshot schemaVersion 2 zůstává beze změny. Rollback je návrat předchozích API/web obrazů, nikoli DB rollback; vrátí však i původní chyby. Před rollbackem či vědomým opakováním je nutné vyjasnit případné nejasné SMTP pokusy, aby nevznikl duplicitní email.
- Další nasazení je samostatný schválený krok: dořešit povinný gate, review/CI, použít nynější `build-images.yml` a `release-candidate-smoke.yml` pro přesný commit/digest, vyřešit blokující obnovu zálohy dle zadání a teprve poté nasadit API/web a provést povolené produkční ověření. Žádná stará dehardening fáze se tímto neotevírá. Budoucí DB změny patří do `docs/operations/standard-production-migration.md`; tento hotfix tuto cestu nespouští.
